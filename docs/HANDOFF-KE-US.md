# 「我们」页 · 网页设计审核交接

本分支交付 `Design/KeUs/` 的独立网页预览。Claude 负责审核、真实接口与原生接入；这里不修改 App 代码、版本、服务器或发布流程。

## 从这里看

从仓库根目录运行：

```sh
python3 -m http.server 8772 --bind 127.0.0.1 --directory Design/KeUs
```

浏览器打开 `http://127.0.0.1:8772/index.html?palette=white`，四款对比为 `http://127.0.0.1:8772/compare.html`。若端口已占用，换一个空闲端口并同步修改访问地址。

请通过本地 HTTP 查看，不要双击用 `file://` 打开。网页需要读取相邻 JSON；浏览器对本地文件的读取限制可能导致日历、动效和详情页没有启动。没有外部服务依赖，不需要安装前端依赖包。

## 已确认的视觉决定

- 只保留浅雾蓝、冷白、暖白、浅米色四款浅色。不提供夜晚模式，也不跟随系统自动变暗。山茶页不直接套深底。
- 英文装饰花体统一 **Pinyon Script**，PostScript 名 `PinyonScript-Regular`。字体与 OFL 许可随包；中文、日期、按钮不改成花体。原生不要换回 Allura 或 Snell Roundhand。
- 四个入口各开独立页面，不做一个包含四个顶部标签的合并入口。标题无蓝色外框；操作控件仍保留键盘焦点提示。
- 荷包余额用蓝条表示可用余额占月上限的比例，储蓄用粉条表示目标完成比例。超支明确显示超出金额，条长限制为 0–100%。
- 产品以柯记账为主，用户也可以修改、删除记录。始终显示原作者“柯记的 / 我记的”；用户修改后追加“我修改”，不冒充原作者。

## 页面与交互

从水面进入 `#purse` 荷包、`#menu` 食单、`#meds` 药盒、`#notes` 纸条；返回进入 `#pond`。四个入口保留 `entry-purse`、`entry-menu`、`entry-notes`、`entry-meds` 的 `data-id`。

- **荷包**：本月剩余、月上限、一起存、问过柯的、当月流水。点月上限/储蓄修改；点记录可修改、确认删除或撤销删除。预算/储蓄汇总本身提供修改，不是可删除的流水。
- **食单**：吃过的、好吃/一般/踩雷、地点、柯的一句话；以及“柯的账本上欠着的”待办。
- **药盒**：早/睡前等时间分组勾选吃了，当前药单显示药名、剂量、时间和作者；支持新增、编辑、停用与变动记录。截图中的示例药 A/B/C 及剂量均为虚构排版数据，不提供用药建议。组勾选仅修改预览状态，不代表真实服药。
- **纸条**：便利贴式提醒待办，可完成、恢复、编辑、删除。提醒时间只是展示，不发送系统通知。
- **排班**：早班、副班、正常班、自定义名称与时间；无班次留空，不显示“休息”。
- **月经**：点日期后选择“来了 / 走了”，开始日算粉色，结束日不算；开放区间只标到示例今天，不预测未来。可撤销最近一次标记。
- **纪念日**：上下滑轮切换在一起、表白日、生日，点击选中名称编辑，点击添加新增。滚轮与数字靠近，数字短暂翻动；减少动态偏好下直接更新。2 月 29 日生日在非闰年按 2 月最后一天计算。

所有数据均为虚构示例，不读取真实健康、财务、聊天或药单。编辑仅在当前页面内保留，刷新重置，不读写 localStorage，不向服务器上传。

## 动效实施入口

保留当前网页作为动作参考，不用静态截图推断运动。

- `fish-motion.js` 的 `pose`：头部预转向、肩部轻摆、沿脊线传播的尾摆，推进与滑行交替；两条鱼节奏不同。`app.js` 的 `drawFish` 用连续条带绘制。
- `app.js` 的 `petalRoutes`、`arrivalGaps`、`newPetal`：沿错开的留白路径落瓣，接触水面后产生涟漪，再淡出。不是整幅图片上下平移。
- 涟漪只由点击水面与花瓣落水触发，鱼和“食单”入口不持续生成水波圈。
- 页面暂停、减少动态、后台、离屏和打开编辑框时停帧。文字倒影随暂停状态停止。

## Claude 接口审核重点与未完成项

`sample-data.json` 保留约定的 verse / moon / calendar / dayDetail / entries 结构。另两份示例文件是网页交互补充，**不代表已经约定新增服务器 API**。请对齐真实接口后再映射到原生。

需要明确补齐的部分：

1. `entries.fresh` 引导鱼游向入口、`badge` 展示尚未接入；鱼目前独立游动。
2. `moon` 字段尚未驱动月相或下一纪念日；月亮还是素材。
3. `dayDetail` 与日历所有字段尚未完整映射。月经区间和纪念日来自补充示例；纪念日天数由事件日期计算，不直接读取 `verse.daysTogether`。
4. 详情页的真实读写、作者权限、冲突处理、删除审计、提醒通知均由 Claude 接入；网页没有模拟柯自动写入。
5. 主导航“柯 / 柯的”只是占位提示，本包只覆盖“我们”页与四个详情入口。

不要把本分支整条合并到当前 App 分支：这是从仓库默认分支创建的设计交付分支，不是最新原生功能基线。取用 `Design/KeUs/` 和本文即可，或仅挑选本次设计提交。
