## 固定的视觉与入口

浅冰蓝雾感背景、淡粉山茶、浅鼠尾草绿叶，保留自然下弯的记忆侧枝和原蓝白蝴蝶。六花用稳定 ID 对接业务，不用数组位置作为业务标识。

中间大花是 **抽屉 drawer**，最下方是 **朋友圈 moments**。这是最终文字对应关系；不要按旧截图互换回来。其余入口为日记、梦、塔罗、记忆。五/六花历史草稿不属于这次交付。

根部 `index.html` 保留已确认的整图效果。分层素材是生成式提取/重建，有局部细节差异；`layers.html` 是校准与接入参考，不能默认为用户已重新验收分层美术。原生首次落地可保留整图花枝，通过同一份归一化点击区域接入口；换分层图前对照定稿确认。

## 坐标如何用

`layout.json` 是位置真值。原点左上；x/width 乘画布宽，y/height 乘画布高。frame 是含透明边距的图层矩形，不是非透明像素范围；`contentBoundsPixels` 仅供检查，导入时不可自动裁边。

原生建议以 390×844 点为设计画布，等比缩放或加安全区，别把图拉伸到任意屏幕比例。定稿网页原比例 853:1844，与该画布不到 0.11% 的差异已标注。真实状态栏、底栏由 App 管理；网页里的状态栏和三项底栏仅是静态效果示意，不要求替换现有 App Tab 架构。

主枝、花、挂签、挂线和停靠中的蝴蝶放进同一摇动父容器；锚点在整画布 (0.95, 0)。若飞行蝶放到独立 overlay，必须先把花的局部坐标变换到世界坐标，不能漏掉枝条旋转。花、挂签均可点；触控区域至少 44×44 pt，避免标签重叠造成入口歧义。

## 蝴蝶与卡片必须绑定同一条真实内容

生产页面使用同一个选定内容对象，例如 `{id, kind, occurredAt, title, excerpt, thumbnail, destination}`。这只是客户端适配契约示意，不是已存在的新 API；沿用 App 现有数据层，不新建服务器接口。

1. 先由真实已落库内容决定当前事件，`kind` 映射到六个稳定入口 ID。
2. 蝴蝶目标花、底部标题、摘要、时间、图片和跳转目标，全部从该对象读取。
3. 新日记对应 diary；新朋友圈对应 moments。不能蝶停朋友圈，卡片仍显示日记文案。
4. 多条未读按真实时间稳定排序，时间相同再按 ID；看过的旧事件不因刷新反复飞。无新事件可静静停在上次花上，不编造“刚刚”。
5. 点击其他花只代表用户导航意图，不自动改写真实事件、已读状态或内容。卡片只有在明确选定另一条真实内容时才随之切换。飞行期间可保留上一条卡片，落定时原子切换目标和卡片；快速连续事件取消旧动画，旧完成回调不得覆盖新事件。

`layers.html` 的按钮仅注入内存示例，不读写网络、本地存储或业务数据；在那里点花会选择该入口的演示内容，方便核对对应关系。定稿 `index.html` 仍是自动巡游与固定卡片，不能直接把它的演示逻辑当生产通知逻辑。

## 点花后怎么展开

现有网页仅实现蝶飞行/停靠、枝摇和暂停，不包含真正业务详情页。分层页增加卡片联动示例和落瓣；也不实现业务路由。

建议展开参数集中在 `motion.json → proposedPageExpansion`：点花先轻缩放反馈，目标花作为转场源，淡出其他装饰后展开详情。不要让用户等完整 3 秒飞行才进入功能。减少动态效果时用短淡入淡出。返回后保留当前事件和停靠点，不重置巡游，不重新标记未读。

## 验证边界

素材校验工具为 `Design/KeCamellia/tools/validate.cjs`；结果摘要见 [review/verification.json](../Design/KeCamellia/review/verification.json)。它检查引用完整、21 张 PNG 的尺寸与 alpha、六入口映射、挂签无字的生成来源、坐标范围及两份清单一致性。

本交付未验证原生 App 的 VoiceOver、真机长时间耗电/帧率、真实通知排序和业务详情页。iOS 接入与真实数据联动由 Claude 实施，发版另行确认。

浏览器实测记录见 [browser-checks.json](../Design/KeCamellia/review/browser-checks.json)，含六入口逐项对应、新朋友圈到达后卡片同步、390×844 窄屏无横向溢出及定稿图片加载检查；对照截图一并存放在该目录。
