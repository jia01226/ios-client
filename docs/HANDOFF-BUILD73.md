## 本轮前端

- 班次模板可新建、自己命名、改名、改一段或两段时间、删除。删除只移出可选列表，日期上的既有名字和时间快照保留。更改模板只更新今天和未来的同类班次，某天单独调整的时间保留。
- 排班仍用 `fetchShifts / setShift / deleteShift`，没有增加服务器字段。班名写 `shift`，具体时段与用户备注写 `note`。模板库存在本机；每个已排日期照旧同步，柯能读取。周、月表点击已排日期直接取消。
- 「玩」空出的中间位置加山屋，八个物件全部可打开。原创 SwiftUI 线条绘图，使用现有主题；没有复制参考仓库的图片或字体。山屋固定走 test1 的 Cookie 会话，只读记忆，唯一写入是用户点提交的小锁信。提交失败留草稿，提交成功后刷新失败也不误报为发送失败。
- 浅色「我们」将纪念日、周班表、月历收在一个「日历」区域，通过日子／周班表／月历切换；纪念日编辑可直接进入。经期的「来了」「走了」放在第一屏，记录与删除可从「经期」打开。深夜保留原布局和色板，补同样的经期入口。

## 需要 Claude 接上的服务器缺口：结束日期

当前 GitHub `goodlove/platform/routes/daily.py` 的 `/api/periods` 只接收 `start_date` 和 `note`，数据库只存开始日期；`deletePeriod` 是删除整条记录，不能拿它表示结束。前端已保留现有开始、查询和删除接口。

前端为「走了」准备了如下**待实现契约**，没有修改或部署服务器：

```http
POST /ke-test1/api/periods/end
Content-Type: application/json
Cookie: 与现有会话一致

{"id": 现有记录ID, "end_date": "YYYY-MM-DD"}
```

服务端应验证记录归属、日期格式以及结束日期不早于开始日期，重复同一结束操作应幂等；成功返回 `{"ok":true}`。`GET /api/periods` 应在对应原记录返回 `end_date`，不新增一个开始记录，也不删除原记录。柯的经期上下文也需要读取该结束日期。

当前未接通时：手机保存待同步结束日期，明确显示「已记本机，待同步给柯」。HTTP 404/400、失败回执、或查询中没有相同 `end_date` 都不会标成已同步；不会删除开始日期。接口接通后，从经期记录点「重试同步结束日期」。

山屋 GET `/api/hut` 与 POST `/api/hut/letter` 按工单提供的契约接入；请 Claude 核对 VPS 实际返回字段（GitHub 默认分支尚未发现山屋实现），尤其整数／字符串 ID、空 `floe`、`letters.reply`。
