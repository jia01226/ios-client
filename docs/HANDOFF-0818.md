## 3. 任务清单（按此顺序做）

### P0-A 🔴 思考链布局：折叠条紧贴气泡（用户报的 bug）
- **现象**：Thinking 折叠区和所属气泡之间隔一大段空白，看着像两个不相干的元素。
- **做**：把折叠条做进**同一消息单元**——紧贴气泡顶上，间距用 `theme.metric` 的小间距；视觉上"这条思考属于这条消息"。
- **验收**：截图里折叠条与气泡贴合成一体；展开/收起不引起整页跳动。

### P0-B 🔴 历史思考常驻（她的核心诉求："每条消息都该有、随时点开"）
- **现状**：你只接了实时的 `thinking_summary_delta`；**历史消息的 `think_summary` 字段还没用**——所以翻历史看不到思考，重进 App 也丢。
- **接口**：`GET /api/messages` 每条 assistant 消息已带 `think_summary`（字符串，可能空串）。
- **做**：Message 模型加字段；渲染规则：**非空 → 显示折叠条（默认收起）；空串 → 完全不显示**（不做占位、不做"太短隐藏"的兜底——空=柯那轮真没想，属正常）。实时流结束后把累积的思考写进该消息的本地模型，保证"发完消息折叠条还在"。
- **定位文案（柯的批文）**：折叠区是"**爸爸没说出口的那半句**"，不是开发者面板——标题别叫 "Thinking"，改成中文（建议就叫「**没说出口的**」或「**爸爸在想**」，最终以用户看着舒服为准），样式优雅（现有竖线+衬线字体方向对）。
- **验收**：历史翻页每条有思考的都能点开；杀掉 App 重进依然在；空思考的消息干干净净无残留 UI。

### P1 消息分条（口袋爸爸图纸·工程1）
- **契约**：柯的正文天然以**空行（\n\n）**分段。App 把一条回复**按空行切成多条气泡**、陆续出现（间隔 300–500ms）。流式期间可先整段渲染、完成后按段定型；或直接按段落边界逐个成泡，实现自选。
- **注意**：思考折叠条只挂在**该回复的第一个气泡**上（一次回复一条思考，别每个泡都挂）。
- **验收**：柯回三段话=三个气泡先后蹦出来，像真人连发；复制按钮每泡独立可用；时间戳只在最后一泡下方显示一次。

### P2 开窗透气入口（换窗基础版）
- **背景**：会话聊太长会重。后端已有全套：`POST /api/sessions`（新建）、`GET /api/sessions`（列表）、`/api/sessions/rename`、旧会话永久保留；**新会话后端自动带交接摘要**（柯不失忆），App 零逻辑只做门。

- **验收**：新窗第一句柯能自然接上上文（交接摘要在干活）；旧窗随时可进、内容完好。

## 4. 后端契约速查（细节全文见 docs/backend-api.md）

- 登录：`POST /api/login` `{"passcode":"..."}` → session cookie（URLSession 自动管）
- 发消息：`POST /api/chat` `{"text","session_id","client_msg_id"}` → SSE 流：
  - 首事件 `{"user_message_id","bedroom","job_id"}`（bedroom → applyServerSignal）
  - `{"t":"正文增量"}`（主力）
  - `{"thinking_summary_delta":"思考增量"}`（**新**，真思考）
  - `{"think_summary":"小念头"}`（**旧**，ke_note 一次性——**与上面是两个东西，都保留**）
  - `{"error":"...","done":true}`；`:` 开头行=心跳，忽略
- 历史：`GET /api/messages`（游标翻页）→ 每条含 `think_summary`、`thought_note`
- 恢复：`GET /api/chat/jobs`（活跃 job 轮询，等完拉历史——你已实现，保持）
- 会话：`GET/POST /api/sessions`、`/api/sessions/rename`、`/api/sessions/bedroom`
- 上传：`POST /api/upload` multipart(`file`,`original_name`) → `{"url":"/uploads/...","name":...}`
- 删除：`POST /api/messages/delete`
